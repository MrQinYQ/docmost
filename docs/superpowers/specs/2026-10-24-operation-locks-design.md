# 同步操作结束释放本地锁

用户要求：不要常驻，相关工作执行完要释放。沿用已有 MCP 生命周期与已明确启用的 MD 保存监听，不新增 daemon；空闲时不持有页面锁。

采用操作作用域：一次 MCP 同步调用及其账本更新完成或失败后在 finally 释放所有本次锁；后台处理每次有限工作也使用独立作用域。同一客户端启动的多个进程共享持久账本，必须在持锁后刷新记录，避免旧缓存覆盖新提交、任务和冲突。多个步骤组成的普通页面更新在服务器工具层共享同一作用域，不能在外部写入中间释放。

备选：只在 close 释放仍会常驻占锁；只在现有函数末尾 unlink 会造成旧内存覆盖和跨进程重复写入，均不采用。先用账本级短事务序列化协作写入，页锁兼容旧进程；各独立状态目录互不阻塞。操作过长时其他写调用有界等待并报告忙，不无限挂起。

账本操作互斥采用唯一参与者文件和有序票号；退出者的唯一文件可在确认 PID 不存在后安全回收，不对共享固定锁路径竞争删除。只有在该互斥内部才回收旧页面锁，存活或无法确认的持有者继续受保护。保留 CAS、Git 分支冲突、未知写入只读对账和知识库任务 fence。只读状态不获得页面锁。

范围：运行时、回归/真实本地验收、Skill 指南。保留认证、来源目录、关联 ID、知识库目的地和待处理任务；不操作业务页面，不清活锁、不终止其他会话。不创建 worktree，不自动提交/push。
