# 本地 Markdown → Docmost → OpenViking

## 用户要求与已确认选择

在本地 Markdown 对应文档写入 Docmost 的同时，增加 OpenViking 同步链路，涵盖创建、修改、明确删除及恢复。只管理已经明确绑定的 MD 页面，不自动导入整个 Docmost 工作区。沿用实际 MCP 进程的生命周期，Docmost 网页正文冲突时暂停。

用户选择完整入库，生成摘要和向量，并明确允许把这些已绑定 MD 内容交给本机 OpenViking 已配置的腾讯 TokenHub 摘要模型。2026-10-14 只读检查确认本机 OpenViking 0.4.19：HTTP 为 `http://127.0.0.1:1933`，摘要为 TokenHub GLM-5.3-Flash，向量为本机 Ollama bge-m3。不保存或输出任何模型密钥。

用户已确认复用现有 OpenViking 用户，并要求遵从 Docmost 空间与父子目录结构。OpenViking 可位于远端；本地未安装 ov 或未配置连接不应导致 Docmost MCP 报错。以下按这次修订实施。

## 方案选择

采用本地私有待同步队列。Docmost 和 OpenViking 的成功状态独立记录，Docmost 内容先获得确认，OpenViking 后处理该版本。

直接在同一个 MCP 调用中串行等待两端最简单，但 OpenViking 摘要处理较慢；第二端失败容易被当作整个操作失败，诱发重复创建或重复追加。独立后台守护进程能继续处理，但改变了用户已经选择的生命周期。私有队列让 MCP 运行期间处理，退出保留进度，下次连接补同步，符合当前选择。

## OpenViking 目标与模型处理范围

复用用户指定的 OpenViking 部署、账户和个人用户。现有本机目标是 personal/qinyequan；不新建用户或要求第二个检索连接，不自动修改现有客户端配置。适配器仅通过 HTTP 调用部署，不要求本机安装 ov、Python 或 OpenViking 服务。

完整内容写入默认向祖先刷新摘要；删除接口同样刷新父目录且没有关闭向上传播的参数。因此用户选择复用时，允许 TokenHub 刷新可能包含该用户已有资料摘要的祖先目录。只新增、修改、删除本链路登记的资源；不导入或改写其他原始资料。正常正文更新仍用限定范围的 reindex，减少不必要的向上摘要处理。

OpenViking 密钥保存在仓库外的 0600 文件，不出现在聊天、命令参数、日志或示例中。安装说明引导用户在自己的终端私密完成；不借用 Docmost Token，不读取模型密钥。对 `/health` 的鉴权检查须核对返回账户和用户；仅 HTTP 200 不足以证明密钥有效。可复用既有 ADMIN 的个人用户，但不改变服务器角色或绕过私有资源访问规则。

## 配置与标识

在已有 `DOCMOST_SYNC_ROOT` / `DOCMOST_SYNC_STATE_DIR` 基础上，新增可选配置：

| 配置 | 用途 |
| --- | --- |
| `DOCMOST_OPENVIKING_URL` | OpenViking 部署根地址；HTTPS，或明确允许的本机 loopback HTTP |
| `DOCMOST_OPENVIKING_API_KEY_FILE` | 仓库外、当前用户所有的私有凭据文件 |
| `DOCMOST_OPENVIKING_ACCOUNT` | 可选的预期账户，用于检查身份，不能替代服务端鉴权 |
| `DOCMOST_OPENVIKING_USER` | 可选的预期用户；默认从鉴权健康信息确认 |
| `DOCMOST_OPENVIKING_ROOT_URI` | 可选私有根；默认 `viking://user/<已确认用户>/resources/docmost-mcp` |

未配置 URL 时行为和工具保持不变，不检查 ov 命令或本机服务。配置远程 HTTPS 地址及私有 API Key 文件即可启用；本机 HTTP 只允许 loopback。部分配置、认证失败或目标暂时不可达只阻塞 OpenViking 子状态，不阻塞 Docmost MCP 启动和既有工具。只读模式绝不写入、重建或删除 OpenViking。显式使用完整摘要与向量处理；供应商由 OpenViking 服务管理，本地 MCP 不直接调用 TokenHub。

布局为 `<root>/<originHash>/<workspaceId>/<空间名--spaceId>/<祖先标题--pageId>/.../<页面标题--pageId>/document.md`，保留 Docmost 空间和父子关系，名称安全转义并限制长度，UUID 防止重名。稳定账本身份仍是部署域名、工作区、页面 UUID；URI 是可变化的布局。正文变更前核对空间与祖先链，不以本地文件夹代替 Docmost 目录。

明确的 MCP 改名、移动操作以及下次本地确认同步会重新检查已登记页面的布局。已确认正文先入库新位置，再删除本链路拥有的旧原文；不得递归删除包含别的登记页或未知文件的父目录。删除已空的旧页目录前核对其全部条目归属；不迁移未登记页。MD 固定目标空间的安全限制继续保留，跨空间移动不会偷偷重绑定本地 MD；结构更新可完成，后续 MD 上传仍要求重新确认关联。

配置或身份变化不把旧任务重新定位到新部署。默认本机根 URI 为 `viking://user/qinyequan/resources/docmost-mcp`。API Key 本身决定身份，不能通过请求头变量把原有密钥切换为新用户。

## 创建与修改

现有 `create_page` 创建任意页面时不自动登记。新建本地 MD 页面由 Agent 在已有授权下完成“`create_page` 新建空目标页 → `bind_markdown` → 查询版本并 `resolve_markdown_sync` 条件写入初始 MD”的流程；既有同步工具已能完成，不新增不受控的创建入口。创建响应丢失时不能重复创建；后续步骤失败须明确报告已创建的页 UUID 和停留阶段。

绑定不修改 Docmost。初始 MD 只有在服务端预览的 `proposedRevision` 同时等于实时与持久化版本时，才作为已确认版本进入 OpenViking。初始两端内容不同则显示等待 Docmost 确认；下一次 MD 保存成功或显式解决冲突后入库，不能把未写入 Docmost 的 MD 提前导入。

普通 Markdown 创建路径生成的编辑器 block ID 与条件同步路径可能不同；因此“文字看起来相同”不等于版本相同。不能通过忽略 ID 或宽松 Markdown 字符串比较绕过上述检查。新建空页后条件上传初始正文能够得到此链路可确认的版本。

MD 自动保存与 `resolve_markdown_sync` 必须继续经过当前原子条件更新接口。只有实时与数据库版本都等于本次目标版本时，才推进 Docmost baseline，同时持久化对应的 OpenViking 待同步意图。网页冲突、403、未知写入结果均不产生可处理的镜像任务。

正文来源是本次确认的 MD 快照；不能稍后重新读取已经发生下一次修改的源文件来代替这个版本。标题、附件、本地图片和反向同步保持在当前范围之外。通过网页或普通 `update_page` 改变远端正文，继续触发 MD 关联冲突，不自动把未经此链路确认的远端内容导出。

## 明确删除、恢复、解除关联

仅 `delete_page` 的明确删除操作触发镜像删除。Docmost 删除会影响后代；写入前先保存本次操作 ID、根 UUID、仍活跃登记的候选页面、可核对的祖先关系和原删除状态。结果核对限定于本次目标子树且确认发生删除状态转换的页面，不能扫描所有登记页并清理更早通过网页删除的无关页面。关系变化或因权限不能证明属于该子树时，暂停该项。403、404、超时不能当成删除证据，也不枚举或导入未登记的隐藏后代。

写前保存删除意图，成功后确认并激活镜像删除任务；响应丢失时先检查各登记页面，不重放 Docmost 删除。删除意图的版本优先于旧正文任务，必须等待或核对先前 OpenViking 处理，避免旧任务随后把资源重新创建。

登记子树按后代优先顺序清理；依赖保存在删除 job 中，延后新的父页删除派发，但不阻止旧已派发正文或索引工作的对账。最终目录清理前后以有界的 `/system/wait` 只读等待摘要和向量队列，补足单个任务终止未覆盖的异步祖先刷新。明确成功的最终删除响应保存为 `prune_verify`，之后超时或重启只等待并检查目录，不重复已确认的删除；未知删除仍保留 fence。全局队列等待可能被该部署的其他工作延长，不取消或清空任何队列，也不保证外部写入者不会随后重新创建资源。

`restore_page` 同样先确定并持久化本次目标子树及原删除状态；只恢复其中仍活跃登记且确认发生恢复状态转换的页面镜像。账本保存最后确认的正文哈希和版本。恢复时重新读取受控 MD，由 Docmost 预览验证其同时匹配实时与持久化正文，匹配后建立新快照；源文件不存在、不匹配或版本变化则暂停，由用户确认本地/合并版本，不自动导出意外的远端正文。已成功的旧正文快照可以清除，不要求永久保留。

本地 MD 消失、改名或变空依然只暂停，不删除 Docmost 或 OpenViking。解除关联停止未来任务并取消尚未开始的镜像工作，不删除现有两端文档；保留的目标账本标记为历史归属，不再作为活跃删除/恢复候选，也不能自动补同步。已提交的任务只能只读对账，不能派发后续工作。

普通暂停（`enabled=false`）、Docmost 冲突或未确认状态下，不派发新的正文镜像任务；已提交任务只读对账。明确 `delete_page` 是新的删除授权，确认相应状态转换后允许删除任务越过普通 MD 正文暂停，防止资源在 Docmost 删除后仍作为正常知识被检索；只读模式及进程退出仍禁止派发。恢复产生新的正文镜像，仍受正文暂停与版本确认约束。

## 队列、持久化与生命周期

每页串行处理，最多沿用现有 50 个关联的有界范围；快速保存可合并尚未开始的旧版本，已派发任务须先完成或对账，避免旧摘要覆盖新正文。

私有状态目录增加受限的正文快照文件：目录 0700、文件 0600、当前用户所有、非符号链接、单份正文最多 1,000,000 字节。现有“状态不保存正文”的文档必须明确更新：关联元数据仍不含正文，待同步快照会暂存正文，确认处理并不再需要恢复后清除；绝不存密码或 Token。异常保存失败不能静默丢弃镜像任务。

写 Docmost 前持久化本次受限快照，作为未确认意图；Docmost baseline 与可处理镜像任务标识同次原子落盘。崩溃恢复仍先通过 Docmost 版本核对确认，再激活镜像；不因重启漏掉已经成功的 Docmost 版本。

同一页面共享当前租约机制，不抢占未知旧租约。EOF、SIGINT、SIGTERM 停止新调度，取消请求，保留未确认状态，释放自有租约。OpenViking 已提交的服务端处理可能继续；下次 MCP 启动查询处理结果，不再发起新的后台进程。

真实验收确认 OpenViking 即使 `recursive:false` 也对目录取得子树锁。增加同一状态目录、账户及私有镜像根的任务租约，直到服务端任务终止才允许另一登记页处理；重启后从持久记录核对仍运行的任务。目录锁超时仅重试索引阶段，不重发正文或 Docmost 写入。

OpenViking API 没有正文 CAS 或业务幂等键。本机租约只能串行本链路，不能约束其他外部写入者；镜像目录应由本链路独占写入。发现目标正文与已知基线不符时暂停，不能宣称跨系统原子事务或 exactly-once。

## OpenViking 协议与成功判断

优先使用内容接口，不使用会解析、拆分和重新命名文档的 `add-resource`。

1. `POST /api/v1/content/write`，固定 URI，`mode: replace`、`processing_mode: vectors_only`、`wait: true`。这是准备正文与向量的阶段；不是用户选择的最终处理结果。
2. `GET /api/v1/content/read`，`raw: true`，比较完整正文摘要。必须分别判断写入结果和向量错误，HTTP 200 不等于成功。
3. `POST /api/v1/content/reindex`，每页独立目录，`mode: semantic_and_vectors`、`recursive: false`、`wait: false`。此阶段生成完整 L0/L1 与向量，并取得可跟踪的 `task_id`；不向上扩散正常修改的摘要处理。
4. `GET /api/v1/tasks/<taskId>` 跟踪完成；`completed` 仍须 `failed_records === 0`，警告及未支持项目需要显示。

未知内容写入先读取正文核对，正文相同只能证明内容已写，不能证明摘要或向量完成。未知 reindex 提交先查询精确资源目录的现存任务；无法确定时暂停，不盲目重复派发。

删除先使用 `DELETE /api/v1/fs` 清理账本拥有的精确原文；确认目录仅剩服务端生成的元数据后，才以 `recursive: true` 清理该空页目录及 L0/L1，不能删除仍包含子页或未知文件的目录。对缺失资源可能残留的向量，用同一精确原文或已证明为空的页目录的 `prune_orphans` 任务补清并检查结果，不对整个镜像根目录清理。删除会刷新父目录摘要，因此目标隔离要求仍适用。

OpenViking 失败只影响镜像状态，Docmost 已确认的结果继续作为成功返回。只在已确认没有业务重复风险的阶段自动补处理；超时等未知写入先对账。认证失效、目标变化、外部写入冲突和无法确认时暂停，给出明确原因。

## 用户状态与文档

扩展现有 `get_markdown_sync_status` 返回每页 OpenViking 目标、确认版本、处理阶段、task ID 和安全错误，不返回正文或密钥。分别显示“Docmost 已同步 / OpenViking 处理中、已同步、失败、待确认”，不能统一显示成功。

增加 `retry_openviking_sync`，输入仅允许活跃登记的 `bindingId`，先只读对账，再处理已经确认可补同步的阶段；不重新创建或追加 Docmost 页面，不接受任意 OpenViking URI，不绕过正文暂停、冲突或未知结果。用户解除、暂停或恢复的语义在中文指南中明确说明。仍从 GitHub 单包安装，不发布 npm 包，也不要求客户端常驻之外的守护进程。

更新中文安装、自验指南与仓库 Skill：账户和密钥获取、仓库外存放、配置部署地址与命名空间、升级重启、处理失败与冲突、临时正文快照的保存和清理。

## 实现边界与验收

根 Agent 负责集成。可并行拆分 OpenViking HTTP/任务客户端、私有快照与队列测试、中文安装说明；Docmost 成功确认入口与队列激活由同一集成任务修改，避免跨文件并发修改确认逻辑。通常无需新增 Docmost 服务端接口。

先做失败复现和针对性测试，覆盖：默认关闭、只读零写入、初始正文不匹配、MD 冲突不入库、Docmost 成功后 OpenViking 失败不重放、响应丢失与重启恢复、快速保存顺序、明确定义的删除/恢复及登记子页、403/404 不误删、外部写入冲突、身份/部署改变、私有快照安全、EOF/SIGTERM。

稳定后在隔离本机 Docmost 合成账户和现有 OpenViking 用户下独立测试根目录验收，使用人工测试 MD：创建并绑定 → 双端读回 → 修改后双端读回 → 空间/嵌套目录布局 → 改名移动与旧路径清理 → 验证摘要/向量与精确目录检索 → 明确删除后原文与索引清理 → 恢复 → 断网、冲突、进程退出和重启对账。另以没有 ov 安装的 PATH 及 HTTP 测试服务验证远端调用与默认不开启。不读取、修改或导入公司现有文档；完成后清理合成页、资源、会话和临时文件。

- 本机 OpenViking 0.4.19：`storage/content_write.py`、`service/reindex_executor.py`、`service/fs_service.py`、`storage/queuefs/semantic_processor.py`、`server/auth/plugins/api_key.py`、`server/routers/admin.py`。
- [官方资源 API](https://github.com/volcengine/OpenViking/blob/main/docs/en/api/02-resources.md)：资源导入与处理模式；实现以本机验证版本的内容/任务接口为准。
