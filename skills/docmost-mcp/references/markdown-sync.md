# 本地 Markdown 自动同步

用于用户明确请求将本地 MD 关联到 Docmost 并在保存后单向自动上传。跟随实际 MCP 服务进程；没有独立守护进程、模型调用、双向同步或文件删除传播。

## 接入

保留现有部署、个人会话/API Key、默认位置与其他客户端配置。在选定作用域中合并两个环境变量：`DOCMOST_SYNC_ROOT` 为用户选择的现有绝对源目录；`DOCMOST_SYNC_STATE_DIR` 为独立私有绝对目录，两者不能互相包含。只操作授权配置作用域；不默认选整个用户目录。私有状态0700/0600存关联和摘要，不存正文/凭据。已有安装从 GitHub更新、单包构建并重启连接；有本地改动先保留，不能reset/覆盖。

服务器必须提供此 fork 的 `pages/sync-state` / `pages/sync-update` 条件同步路由。MCP安装不会升级服务器。缺少接口报告 `UNSUPPORTED_DEPLOYMENT`，不能退回普通 `update_page`、数据库或浏览器 Cookie 来自动上传。已有邮箱/密码会话方式继续适用；不要求企业 Key，不涉及许可绕过。

配置后发现实际工具：可写模式26个、只读11个；无同步配置仍22/10。只读模式只有状态扩展，不监听上传。状态中报告具体限制，不能以工具注册证明部署支持。

## 工具

| 工具 | 参数 | 作用 |
| --- | --- | --- |
| `bind_markdown` | `filePath`（源目录内相对.md）, `pageId`（规范UUID）, `enabled?`（默认true） | 建立双方当前基线，不初始上传；启用后未来保存替换整个页面正文。 |
| `get_markdown_sync_status` | `bindingId?` | 列表读取缓存；指定关联时只读取得 `currentRevision` / `currentPersistedRevision`，不上传、不重置基线。 |
| `set_markdown_sync` | `bindingId`, `action:pause|resume|unbind` | 暂停、保持基线恢复、解除关联。 |
| `resolve_markdown_sync` | `bindingId`, `expectedRevision`（当前远端64位hex版本） | 用户明确选择本地/合并内容后，条件替换并恢复；远端再次变化仍拒绝。 |

先用现有工具读取/确认目标UUID。根目录配置仅限定文件访问范围；目标页面与用户上传授权必须明确。不得凭标题猜页ID，绑定后也不因默认空间变更而改目标。拒绝越界、符号链接、非普通文件、无效UTF-8、空白、>1,000,000字节。正文之外的标题、父页、空间、本地图片附件不自动同步。

## 冲突与恢复

当前同步接口读取实时owner Ydoc，原子比较版本后更新。正文内容不同于原基线时暂停；普通更新时间和Markdown往返字节差异不作为原子版本。只保护服务端已收到的协作状态，不能阻止后续授权修改。

冲突后读远端并让用户决定保留/合并。恢复监听不重置冲突基线；通过 `get_markdown_sync_status({bindingId})` 取得当前 `currentRevision`，将其作为显式解决的 `expectedRevision`，配合用户授权的本地/合并正文。`remoteRevision` 是旧基线，不能拿来代替当前版本。不能把读页面或查询状态解释为覆盖授权。

网络/存储不确定时持久化pending并先核对，不重发。只有实时与持久化版本均确认目标才报告成功。401交用户终端重新登录并重启；403不切管理员；身份或空间变化重新确认关联。多客户端共享状态目录，通过页面租约避免重复上传；不删除未确认已结束进程的租约。

MCP EOF或退出停止新上传，但已发出请求可能完成，重启后先对账。文件删除/改名/暂时变空暂停，不删远端。解除关联保持双方内容。用户自验按“关联无初始上传→保存读回→网页改动冲突→合并后显式解决→暂停/退出后不上传→只读权限”执行，须事先指定授权测试页面。
